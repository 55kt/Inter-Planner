# Inter Planner — план и видение

> Живой документ. Обновляется, когда меняется видение. Задача — держать всё в одном месте, чтобы ничего не забыть, а MVP оставался маленьким.
> Последнее обновление: 2026-08-26

## Что это

Локальное macOS-приложение — доска-планировщик в духе Milanote. На доске лежат элементы (карточки и ресурсы), их можно двигать, растягивать, соединять стрелками и группировать. Планировать можно что угодно: сценарий, книгу, проект.

---

## Ключевая идея модели (важно)

Раньше мы думали «карточка *содержит* контент» (`Card.content` как enum текст/фото/…). Новое видение чище и мощнее:

- **Карточка — это контейнер (коробка) с метаданными.** Сама по себе она не «текст» и не «картинка».
- **Ресурсы — самостоятельные сущности** (текст, картинка, код, ссылка, документ). Они могут лежать **и внутри карточки, и отдельно на доске** — это один и тот же тип в обоих местах.

Отсюда — три уровня:

1. **BoardItem** — всё, что лежит на доске. Общая «оболочка размещения»: `id`, `position`, `size`, `zIndex`, `isPinned`. Элемент — это либо карточка, либо ресурс.
2. **Card** — контейнер-элемент. Свойства: `title`, `subtitle`, `color`, `createdAt`. Держит дочерние элементы `[BoardItem]` — ресурсы **и** другие карточки (вложенность разрешена).
3. **Resource** — «лист» с контентом. У каждого вида — свои свойства.

Плюс две «горизонтальные» сущности поверх элементов:

- **Connection** — стрелка/связь между двумя элементами (ребро графа). Хранится **отдельным списком**, а не полем внутри элемента.
- **Group** — сгруппированный набор **любых** элементов (карточки, картинки, ссылки, файлы). Складывается в «стопку» с анимацией, разворачивается/сворачивается кнопкой (поведение — в разделе «Взаимодействия»).

### Виды ресурсов и их свойства

| Ресурс | Свойства (черновик) |
|---|---|
| Text | шрифт, размер, цвет, начертание |
| CodeBlock | язык, тема подсветки (напр. Monokai), номера строк, моно-шрифт |
| Image / File | ссылка на файл в хранилище, натуральный размер |
| Link (YouTube / Spotify / …) | URL, preview-метаданные (позже) |
| Document | ссылка на файл |

### Архитектурные решения

- **Ресурс не зависит от карточки** — одна и та же сущность на доске и в карточке.
- **Связи (стрелки) — отдельный список рёбер** `from itemID → to itemID`, не поле элемента.
- **Медиа хранится ссылкой** (имя файла в хранилище приложения), а не байтами. Байты — на диске, модель лёгкая и `Codable` в JSON.
- **Карточка не знает про доску** — доска владеет своими элементами.
- **PaletteColor** — общий enum цвета → ассеты (светлая/тёмная тема).
- **Board** — `id`, `title`, `icon`, `color`, держит `[BoardItem]` + `[Connection]` (+ группы). Приложение держит `[Board]`.
- Точная кодировка в Swift (enum `.card`/`.resource` внутри `BoardItem` vs протокол) — решим, когда дойдём до реализации. Концептуально: общая «оболочка размещения» + вид контента.

## Взаимодействия (поведение)

- Создать карточку на доске → назвать → подзаголовок → цвет → **закрепить** (зафиксировать, чтобы не двигалась).
- **Боковая панель** со всеми ресурсами. Ресурс перетаскивается: **в карточку** (там ресурсы группируются) или **на доску** отдельно.
- От любого элемента можно тянуть **стрелку** к другому → последовательности/связи.
- Элементы **растягиваются мышью**, как окно Finder (картинка PNG, файл и т.д.).
- **Выделение и hover подсвечиваются.** Выбранные элементы и элемент под курсором — с подсветкой.
- **Группировка любых элементов.** Выделил карточку / картинку / ссылку / файл → «Сгруппировать» → с анимацией складываются в **стопку**, но каждый элемент чуть выглядывает (для наглядности). Кнопка развернуть/свернуть. При наведении на группу элементы выезжают чуть больше и подсвечиваются.

## Дорожная карта (по фазам)

Смысл фаз — строить маленькими срезами и **не тащить сложное вперёд простого**.

### Фаза 0 — фундамент ✅ (сделано)
- Холст доски + точечный фон (dice-сетка).
- Цвета темы из Asset Catalog (светлая/тёмная).
- Модель `Card` + `PaletteColor`.
- Статичная вёрстка `CardView`.

### Фаза 1 — MVP «живая доска» (текущий фокус)
1. Показать 2–3 захардкоженные карточки на доске (`ForEach` + `.position`).
2. Перетаскивание карточки (`DragGesture`) → сюда же приходит `BoardViewModel` (reference type, мутируем позиции).
3. Добавление карточки по кнопке.
4. Редактирование `title` / `subtitle` прямо в карточке.
5. Сохранение доски в JSON (`Codable`) + загрузка при старте.
6. Удаление карточки.

### Фаза 2 — ресурсы, база
- Ввести сущность `Resource`.
- Текстовый ресурс внутри карточки.
- Боковая панель ресурсов, drag текста из панели в карточку.

### Фаза 3 — больше видов ресурсов
- Image (`PhotosPicker` + хранение файла), File, Link (preview позже), CodeBlock (тема подсветки позже).

### Фаза 4 — «силовые» фичи доски
- Ресурсы отдельно на доске (не только в карточке).
- Растягивание элементов мышью.
- Много досок + боковая панель досок.

### Фаза 5 — граф и группировка
- Стрелки/связи между элементами.
- Группировка (+ анимация).
- Карточка внутри карточки (вложенность).

### Позже / может быть
- Бесконечный холст pan/zoom.
- Ручной переключатель темы (system/light/dark, `@AppStorage`).
- iCloud/синхронизация, undo/redo, живые preview ссылок, реальная подсветка синтаксиса.

## Открытые вопросы (решить по ходу)

Решено: карточка может держать другую карточку ✅ · группа — из любых элементов ✅ · `isPinned` — свойство любого элемента доски ✅

- Дети **внутри** карточки — со свободными позициями (как на доске) или списком/стопкой? (Снаружи вложенная карточка имеет `position`; внутри — пока не решено.)
- Растягивание: как ведёт себя текст vs картинка при ресайзе (перенос текста vs масштаб картинки)?
- Группа при сохранении — отдельная сущность со списком id, или флаг на элементах?
